# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Synthesis flow for the `mmForMLP` design (a matrix-multiply accelerator for MLP inference, generated by SpinalHDL, instantiating two `mem55lpw1024d16sp` and two `mem55lpw256d16sp` SRAM macros). The flow is driven by Make + Tcl, targeting Cadence Genus (currently the only implemented tool), with scaffolding for Synopsys DC and Formality. Technology is a 55 nm HL055P 7M6X1T4_RDL process with RVT/LVT standard cells.

## Commands

```sh
make init              # create tech -> /mnt/sharefile/EE291F/3003/tech.lab symlink (required before first run)
make genus             # run all Genus stages in one process via script/genus/genus.tcl
make genus-elaborate   # run one stage only (also: genus-generic, genus-map, genus-opt, genus-final)
make genus-shell       # interactive Genus session in build/genus
make genus-clean       # remove build/genus
make clean             # remove build/
```

`make tcl-check` is declared in the [Makefile](Makefile) but [script/check.tcl](script/check.tcl) does not exist yet — the target currently fails.

`tech/` and `build/` are gitignored. The `tech` symlink must exist for any tool run; `make init` recreates it.

## Architecture

### Make layer

[Makefile](Makefile) holds only project-wide settings (`PROJECT`, `BUILD_DIR`, `SCRIPT_DIR`, `RUN_STAMP`, `GIT_COMMIT`) and includes one `tool-*.mk` per tool. Each `tool-*.mk` follows the same shape and is the place to add stages:

- `*_MAIN` is the entry Tcl script, overridable per stage (e.g. `make genus genus GENUS_MAIN=script/genus/03_map.tcl`).
- Every run `cd`s into the tool's build dir and appends the git commit hash plus the exact `make` command line to a `<timestamp>-git-commit.txt` record next to the timestamped `.log` and `.cmd`.
- Stage targets are thin wrappers that re-invoke `make` with a different `*_MAIN`; `RUN_STAMP` is re-evaluated in the sub-make, so each stage gets its own log timestamp.
- `tool-dc.mk` and `tool-formal.mk` are wired up but their script directories ([script/dc/](script/dc/), [script/formal/](script/formal/)) do not exist yet.

### Tcl layer

Shared configuration lives in [script/](script/) and is loaded by each tool's `env.tcl`:

- [path.tcl](script/path.tcl) — derives all directory variables from `PROJECT_DIR` (resolved from `info script`). Every other config file depends on these being sourced first.
- [tech.tcl](script/tech.tcl) — PVT corners, cell/macro library names, and every derived file path (`LEF_LIST`, `LIB_LIST_FF/SS`, `DB_LIST`, `QRC_LIST`, `GDS_LIST`, `NDM_LIST`).
- [design.tcl](script/design.tcl) — design name, clock/reset names, RTL and SDC inputs, and the output paths each tool writes to (`GENUS_NETLIST`, `GENUS_SDC_MAIN`, `DC_NETLIST`, `DC_SVF_*`). This is the single place output filenames are defined.
- [helper.tcl](script/helper.tcl) — `stage_make_dir` plus per-vendor helper procs: `s_*` for Synopsys, `c_*` for Cadence.
- [mmmc.tcl](script/mmmc.tcl) — the one MMMC definition (library sets, RC corners, constraint modes, opconds, timing/delay corners, analysis views). Branches on the global `TOOL` to pick the SDC source. Genus reads it with `read_mmmc`.

[script/genus/env.tcl](script/genus/env.tcl) is the per-tool bootstrap: it sets `TOOL`, sources the shared files in dependency order, then [setting.tcl](script/genus/setting.tcl). [genus.tcl](script/genus/genus.tcl) sources `env.tcl` and then loops over `GENUS_STAGES` — so a bare `make genus` runs the full flow in a single Genus process, while the per-stage targets run one script each.

### Genus stage scripts

`01_elaborate` → `02_generic` → `03_map` → `04_opt` → `05_final`, listed in `GENUS_STAGES` in [setting.tcl](script/genus/setting.tcl).

Each stage follows an identical skeleton: source `env.tcl`, set `STAGE_NAME`/`STAGE_DIR`/`STAGE_DB`, `read_db` the previous stage's `${DESIGN}.db`, apply a stage-specific clock uncertainty, run the synthesis command, `write_snapshot` + `report_summary`, `write_netlist`, `write_db`. Config → Run → Report → Export → Save, with banner comments.

Things to know before editing a stage:

- **Stages are chained by hardcoded DB paths**, not by Make dependencies. `02_generic` reads `${GENUS_BUILD}/01_elaborate/${DESIGN}.db`. Reordering or renaming a stage means editing the `read_db` in the next one. There is no timestamp/dependency tracking — running stages out of order silently uses a stale DB.
- **`stage_make_dir` deletes and recreates the stage directory** (`file delete -force`). Re-running a stage wipes its previous reports and netlist.
- **Clock uncertainty is tightened per stage** via `c_sdc_modify_uncertainty` with values in `setting.tcl` (`GEN` 1.25 → `MAP` 1.00 → `OPT` 0.75 → `GENUS` 0.50 ns setup). The uncertainty in the input SDC is only the starting point; the flow overrides it at every stage.
- **Report file prefixes come from the `write_snapshot -tag`**: `syn_generic`/`syn_map`/`syn_opt` in stages 02–04, and `genus` (with `-innovus`, for downstream handoff) in 05. Only the final stage exports to the paths in `design.tcl`; earlier stages write into their own directory.
- Stage 05 writes the SDC per constraint mode from `SDC_LIST`, excluding `set_dont_touch_network` and `set_dont_use`.
- `01_elaborate` also applies `DONT_USE_CELL_PATTERNS` (delay/antenna/fill/tap/clock/gating/tie cells and min/max drive strengths) by expanding wildcards to real library cell names via `c_get_base_cell_names`.

## Conventions

- Comments use banner blocks: `# ---...--- #` followed by a short title, with a one-line comment above each command explaining intent. Match this style.
- Config values are UPPER_SNAKE_CASE Tcl variables declared in the `script/*.tcl` config files; stage scripts should reference them rather than hardcoding literals.
- Design constants (clock period 10 ns, input/output delay ratios, output load) live in [input/sdc/mmForMLP.sdc](input/sdc/mmForMLP.sdc); the design/clock/port names must stay in sync between that file and [script/design.tcl](script/design.tcl).
