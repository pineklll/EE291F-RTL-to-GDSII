# mmForMLP Synthesis Flow

RTL-to-netlist synthesis flow for **mmForMLP**, a matrix-multiply accelerator for MLP inference. The RTL is generated by SpinalHDL and instantiates four SRAM macros (two 1024×16, two 256×16).

The flow is Make-driven with Tcl scripts, targeting **Cadence Genus**. Scaffolding for Synopsys DC and Formality is in place but not yet implemented.

| | |
|---|---|
| Design | `mmForMLP` |
| Clock | `main_clk` on port `clk`, 10 ns period |
| Reset | `resetn`, active low |
| Technology | HL055P_7M6X1T4_RDL (55 nm), RVT + LVT standard cells |
| Corners | `view_ss_ccw` (1.08 V, 125 °C, cworst) / `view_ff_ccb` (1.32 V, −40 °C, cbest) |
| Tool | Genus 25.10-p002 |

## Prerequisites

- `make`, `tclsh`, and `genus` on `PATH`
- Access to the shared technology directory at `/mnt/sharefile/EE291F/3003/tech.lab` (libraries, LEF, QRC, GDS, NDM)

## Quick Start

```sh
make init        # link tech/ to the shared technology directory (required once)
make genus       # run the full synthesis flow
```

`make init` creates a `tech` symlink that every tool invocation depends on. Both `tech/` and `build/` are gitignored, so `make init` must be run after a fresh clone.

## Flow Stages

The flow is split into five stages. `make genus` runs all of them sequentially in a single Genus process; each can also be run individually.

| Stage | Command | Action |
|---|---|---|
| 01_elaborate | `make genus-elaborate` | Read MMMC, LEF, and RTL; elaborate; apply dont-use cells |
| 02_generic | `make genus-generic` | `syn_generic` — technology-independent optimization |
| 03_map | `make genus-map` | `syn_map` — map to standard cells |
| 04_opt | `make genus-opt` | `syn_opt` — optimize the mapped netlist |
| 05_final | `make genus-final` | Export the final netlist and SDC |

Each stage reads the previous stage's database, so **the stages must be run in order**. There is no dependency tracking — running a stage on its own reuses whatever database the prior stage last left behind.

> **Note:** every stage deletes and recreates its own output directory at startup. Re-running a stage discards its previous reports and netlist.

Other targets:

```sh
make genus-shell    # interactive Genus session in build/genus
make genus-clean    # remove build/genus
make clean          # remove build/
```

## Outputs

Final results land in `build/genus/05_final/`:

| File | Contents |
|---|---|
| `mmForMLP_syn.v` | Final gate-level netlist |
| `mmForMLP_syn_func_main.sdc` | Exported constraints for the `func_main` mode |
| `genus_*.rpt` | QoR, area, gates, and per-corner timing reports |
| `mmForMLP.db` | Genus database |

Stages 02–04 write the same set of reports into their own directories, prefixed `syn_generic_`, `syn_map_`, and `syn_opt_` respectively, plus a `netlist.v` at each step. Comparing these prefixes across directories is the way to track how the design evolves stage by stage.

Each `make` run also records a timestamped `.log`, a `.cmd` command transcript, and a `-git-commit.txt` capturing the commit hash and exact command line — so any report can be traced back to the code that produced it.

## Configuration

All settings live in Tcl config files under `script/`; stage scripts reference these variables rather than hardcoding values.

| File | Purpose |
|---|---|
| [script/path.tcl](script/path.tcl) | Directory layout, derived from the project root |
| [script/tech.tcl](script/tech.tcl) | PVT corners, library names, and all technology file paths |
| [script/design.tcl](script/design.tcl) | Design name, clock/reset names, inputs, and output paths |
| [script/helper.tcl](script/helper.tcl) | Shared procs (`stage_make_dir`, per-vendor helpers) |
| [script/mmmc.tcl](script/mmmc.tcl) | MMMC setup: library sets, RC corners, constraint modes, analysis views |
| [script/genus/setting.tcl](script/genus/setting.tcl) | Genus-specific settings: stage list, synthesis effort, dont-use cells |

**Constraints** are in [input/sdc/mmForMLP.sdc](input/sdc/mmForMLP.sdc) (clock period, I/O delays, output load). The clock, reset, and design names there must stay in sync with [script/design.tcl](script/design.tcl).

**Clock uncertainty is tightened at each stage** rather than set once. The flow overrides the SDC value via `c_sdc_modify_uncertainty`, stepping setup uncertainty down from 1.25 ns (generic) to 0.50 ns (final) as the design becomes more realistic. These values are in `setting.tcl`.

## Extending the Flow

To add a synthesis stage:

1. Create `script/genus/NN_name.tcl` following the existing stage skeleton: source `env.tcl`, set `STAGE_NAME`/`STAGE_DIR`/`STAGE_DB`, `read_db` the previous stage, run the synthesis command, `write_snapshot` + `report_summary`, `write_netlist`, `write_db`.
2. Insert the stage name into `GENUS_STAGES` in [script/genus/setting.tcl](script/genus/setting.tcl).
3. Add a `genus-<name>` target to [tool-genus.mk](tool-genus.mk) following the existing pattern.

Stages are chained by hardcoded database paths, so inserting a stage in the middle also requires updating the `read_db` line in the stage that follows it.

To target a different design, edit [script/design.tcl](script/design.tcl) and add the corresponding RTL and SDC under [input/](input/).
